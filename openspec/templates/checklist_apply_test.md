# Applyテストレビューチェックリスト

対象: テストタスクの成果物（`test_plan.md`・テストコード・テスト実行結果・カバレッジレポート・画面キャプチャ）

レビュアー: QA Reviewer Agent

## 仕様妥当性検証・TDD実践

| #   | 観点                                                                                           | 判定     | コメント |
| --- | ---------------------------------------------------------------------------------------------- | -------- | -------- |
| 1   | `specs/` の全要件・全 Scenario がテストケースとして漏れなくコード化されているか                | ✅/❌/⚠️ |          |
| 2   | `test_plan.md` の全テストケースID（`UT-*`, `DT-*`, `IT-*`, `ST-*`, `E2E-*`）が実装されているか | ✅/❌/⚠️ |          |
| 3   | 仕様変更の意図（What/Why）および不具合修正（`fix`）の再現ケースを検証するテストになっているか  | ✅/❌/⚠️ |          |
| 4   | TDD Red（実装前にテストが意図通り失敗すること）を実際に実行確認し、記録しているか              | ✅/❌/⚠️ |          |

## 単体テスト網羅性（C0 / C1 / C2・同値分割・境界値）

| #   | 観点                                                                                                       | 判定     | コメント |
| --- | ---------------------------------------------------------------------------------------------------------- | -------- | -------- |
| 5   | **C0（命令網羅 / Line）**: 全体 80%以上（新規・変更差分 90%以上）を達成しているか                          | ✅/❌/⚠️ |          |
| 6   | **C1（分岐網羅 / Branch）**: 全体 80%以上（新規・変更差分 85%以上）を達成し真偽両経路を通っているか        | ✅/❌/⚠️ |          |
| 7   | **C2（条件網羅 / Condition）**: 複合条件式のデシジョンテーブル全組み合わせが網羅されているか（100%）       | ✅/❌/⚠️ |          |
| 8   | **数値・文字列境界値**: `min-1`, `min`, `max`, `max+1`, `0`, 負数, 空文字, 空白, 特殊文字がテストされたか  | ✅/❌/⚠️ |          |
| 9   | **コレクション・日時境界値**: 空 `[]`, 1件, 複数件, 上限件数, 境界時刻/タイムゾーン/うるう日が網羅されたか | ✅/❌/⚠️ |          |
| 10  | 異常系・エラーケース（不正引数・例外送出・エラー戻り値）がテストされているか                               | ✅/❌/⚠️ |          |

## E2Eテスト・UI実画面検証

| #   | 観点                                                                                                                       | 判定     | コメント |
| --- | -------------------------------------------------------------------------------------------------------------------------- | -------- | -------- |
| 14  | **Happy Path & Negative/Recovery Path**: 正常操作フローおよびエラー発生→修正→再実行の回復フローが網羅されているか          | ✅/❌/⚠️ |          |
| 15  | **ゼロ設定・初回起動検証**: APIキー未設定・未ログイン・データ0件の初期状態で操作不能に陥らず案内・フォールバックするか     | ✅/❌/⚠️ |          |
| 16  | **名ばかりE2Eでないか**: バックエンド関数結合のみで済ませず、プレゼンテーション層（UI/CLI/API）を通貫検証しているか        | ✅/❌/⚠️ |          |
| 17  | **UIモック忠実再現（GUI/Web）**: 実画面キャプチャ（PNG）を出力し、`mockup.html` との乖離・崩れ・文字同化がないか確認したか | ✅/❌/⚠️ |          |
