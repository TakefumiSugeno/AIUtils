# Proposal: redesign-review-framework

## Meta

- **Level**: L2
- **Type**: refactor

## Why

OpenSpec拡張キット（openspec-kit）におけるレビュー機構は、現在タスクごとに20項目以上のチェックリスト表を埋めさせる運用となっている。
しかし、事前実装ルール（config.yaml）と事後チェックリストの項目がほぼ同一であるため、AIによるレビューが「事前指示通りに作られていることの確認（同語反復・トートロジー）」に終始し、レビュー指摘がほとんど発生せず形骸化している。
また、1つの変更につき100〜200回以上のチェック項目生成が発生し、時間・トークンを浪費するとともに、肝心の潜在バグやエッジケースを見落とす要因となっている。
本変更では、成果物の種類に応じた挑戦的アプローチ（破壊テスト実行・悪魔の代弁者・ブラインド突合・特化ペルソナ）を導入し、形式的な書類仕事を廃止して真にバグや技術的負債を暴く実効的なレビュー機構へと再設計する。

## What Changes

- **チェックリストのQ&A型・挑戦的アプローチへの刷新**:
  - `checklist_propose.md`: 22項目表を廃止し、「ブラインド比較（要件先出し突合）」「故障シミュレーション」「テストの死角告発」「初心者ペルソナによるZero-State/Error-State検証」の成果物別設問へ刷新。
  - `checklist_apply_impl.md`: 単なる目視確認表を廃止し、「Adversarial QA（例外を吐かせる破壊テストの作成・実行）」＋「30%コード削減・過剰抽象化の告発」へ刷新。
  - `checklist_apply_test.md`: 「トートロジーテスト（実装式のコピペ期待値）告発」＋「甘いアサーション・無意味なモックの告発」へ刷新。
  - `checklist_archive.md`: 20項目表を廃止し、「隠された技術的負債・妥協点の自白」＋「初見エンジニア視点での背景（Why）欠落指摘」へ刷新。
  - `review_record.md`: 表形式の記号埋めから、設問回答・破壊テスト実行ログ・指摘対応の記録形式へ刷新。
- **レビュアーエージェントプロンプトの更新**:
  - `qa-reviewer.md`: 単なるカバレッジ確認係から、「落とすテストを作成・実行して堅牢性を検証する敵対的エージェント」へ更新。
  - `pg-reviewer.md`: チェックリスト埋め係から、「コード潔癖症・手抜き告発・30%削減リファクタ提案エージェント」へ更新。
  - `se-reviewer.md`: 「外部依存ハング・通信瞬断時の連鎖崩壊をシミュレートするエージェント」へ更新。
  - `user-reviewer.md`: 「せっかち初心者（データ0件・エラー時の手抜きUI告発）エージェント」へ更新。
- **ゲート検証スクリプトの改修**:
  - `verify-gate.ps1` / `verify-gate.sh`: 「`✅/❌/⚠️` 表の未記入チェック」を廃止し、新フォーマット（挑戦的設問への回答、破壊テスト結果、LGTM判定）の検証に対応。
- **ワークフローと設定の最適化**:
  - `config.yaml` / `AGENTS.md` / `.agents/workflows/sdd-*.md`: 機械判定可能な項目（フォーマット、静的解析、カバレッジ、skip放置）をLLMレビューから完全分離し、スクリプトに任せる運用ガイドラインを明確化。

## Non-goals

- 機械的検証ツール（Linter、フォーマッタ、カバレッジ測定ツール、テストランナー）自体の置き換えや独自実装。
- 人間による最終PRレビューやマージ合意プロセスの廃止。

## Acceptance Criteria

### Given/When/Then

1. **Given**: Applyフェーズでプロダクションコードが実装された状態
   **When**: `qa-reviewer` サブエージェントがレビューを実行した時
   **Then**: 静的なチェックリスト表ではなく、実装を例外終了またはアサーション失敗させる破壊テストを作成・実行し、その成否によって堅牢性を客観評価すること。

2. **Given**: Proposeフェーズで仕様書（`specs/`）が作成された状態
   **When**: `user-reviewer` / `se-reviewer` がレビューを実行した時
   **Then**: 仕様書をそのまま追認するのではなく、背景（`proposal.md`）から独自推論した異常系と照合して仕様書の抜けを指摘すること。

3. **Given**: 新形式で記述された `reviews.md` が存在する状態
   **When**: `verify-gate.ps1 -Gate propose` または `-Gate apply` を実行した時
   **Then**: 旧来の `✅/❌/⚠️` 記号の有無ではなく、新設問への回答および LGTM 判定を正しく検証して合否を判定すること。

## Impact

- `openspec-kit/` 配下のテンプレート、エージェント定義、検証スクリプト。
- 本リポジトリの `openspec/` 配下のテンプレート、エージェント定義、検証スクリプト、設定ファイル。
- 今後このキットを導入する全プロジェクトにおけるレビュー体験（トークン消費の削減、開発速度の向上、バグ検出率の向上）。
