# review-framework Specification

## Purpose

AI駆動開発において、エージェントによる同語反復（トートロジー）や形式的チェックリスト埋めによるレビューの形骸化を排除し、成果物に応じた挑戦的アプローチ（破壊テスト実行・悪魔の代弁者・ブラインド突合・特化ペルソナ）によって潜在バグと技術的負債を確実に検出・検証するレビューフレームワークを提供する。

## Requirements

### Requirement: 成果物別挑戦的レビュープロトコル

システムは、レビュー対象成果物の種別（仕様書、設計書、UIモック、実装コード、テストコード、引き継ぎ書）ごとに、トートロジーを排除した挑戦的設問およびレビュープロトコルを提供しなければならない（SHALL）。

#### Scenario: 仕様書のブラインド比較レビュー

- **WHEN** レビュアーが仕様書（`specs/`）のレビューを実施する
- **THEN** レビュアーは背景（`proposal.md`）から独自推論した異常系・境界条件を先に出力し、実際の仕様書との差分から抜け漏れを指摘しなければならない。

#### Scenario: UIモックの初心者ペルソナレビュー

- **WHEN** レビュアーがUIモック（`mockup.html`）のレビューを実施する
- **THEN** レビュアーはデータ0件の初期状態（Zero-State）およびエラー発生時の回復導線（Error-State）の不備を指摘しなければならない。

### Requirement: 実装コードの破壊的テスト検証（Adversarial QA）

システムは、Applyフェーズにおける実装コードレビューにおいて、実装コードを例外終了または不正戻り値に倒す破壊テストケースを作成・実行して堅牢性を判定しなければならない（SHALL）。

#### Scenario: 実装コードの欠陥検出

- **WHEN** レビュアーが作成した破壊テストコードが実行時に例外またはアサーション失敗（Red）を引き起こす
- **THEN** レビュアーは `LGTM: false` と判定し、失敗ログと共に対象コードの問題点を指摘しなければならない。

#### Scenario: 実装コードの堅牢性確認

- **WHEN** レビュアーが破壊テストを作成しても例外や不正出力を発生させられずテストがパスする
- **THEN** レビュアーは実装の堅牢性が確認されたとして `LGTM: true` を判定しなければならない。

### Requirement: テストコードのトートロジー・甘いアサーション検出

システムは、実装されたテストコードに対して、実装ロジックのコピペによるトートロジーアサーションや、事実上何も検証していない甘いアサーションを検出しなければならない（SHALL）。

#### Scenario: トートロジーアサーションの検出

- **WHEN** テストコードの期待値計算にプロダクションコードと同一の計算式が使用されている
- **THEN** レビュアーは固定リテラル値による検証への修正を指摘しなければならない。

### Requirement: レビュープロトコルの機械的フェーズゲート検証

フェーズゲート検証スクリプト（`verify-gate.ps1` / `verify-gate.sh`）は、レビューフォーマットの必須設問への回答、破壊テスト結果、および最終LGTM判定を機械的に検査しなければならない（SHALL）。

#### Scenario: レビュープロトコル検証の正常通過

- **WHEN** `reviews.md` に各必須設問への具体的な回答と最終的な `LGTM: true` が記録されている
- **THEN** ゲート検証スクリプトは `PASS` を出力し、終了コード 0 で正常終了しなければならない。

#### Scenario: レビュー指摘未解決時のゲート停止

- **WHEN** `reviews.md` の最新判定が `LGTM: false` であるか、未回答の必須設問が存在する
- **THEN** ゲート検証スクリプトは `FAIL` を出力し、終了コード 1 で処理を停止しなければならない。
